PR Layers setup

PR Layers groups a large pull request into ordered layers so you can review it bottom-up. It runs entirely in your browser and only reads from GitHub, using a fine-grained personal access token that you create and paste here. No app registration, no backend.

Current token

1 · Create a read-only token on GitHub

Opens

  1. Token name: pre-filled as PR Layers (read-only).
  2. Expiration: pre-filled to 90 days. Shorter is fine; avoid "No expiration".
  3. Resource owner: pick your organization (e.g. Wayground). If it isn't listed and the org uses SAML SSO, first open the org on github.com and sign in through SSO, then reload the token page. Fine-grained tokens are SSO-authorized at creation, so there's no separate "Configure SSO" step.
  4. Repository access: Only select repositories and choose the repos you review (GitHub can't pre-fill this). "All repositories" also works but grants more than needed.
  5. Permissions → Repository permissions: Pull requests: Read-only and Contents: Read-only (pre-filled). Metadata: Read-only is added automatically. Add nothing else: no "Read and write", no account or organization permissions.
  6. Click Generate token. If your org requires approval, the token stays pending (public repos only) until an admin approves it.
  7. Copy the token (starts with github_pat_).

2 · Paste and validate

Why the checkbox? GitHub doesn't let an extension read a fine-grained token's permissions, so write access can't be detected automatically. Classic tokens are rejected outright. PR Layers itself only ever sends GET requests.

Privacy

The token is stored in chrome.storage.local on this device (restricted to the extension itself, not readable by github.com pages or the in-page widget) and sent only as the Authorization header of GET requests to api.github.com. PR code is processed locally and never sent anywhere else.
