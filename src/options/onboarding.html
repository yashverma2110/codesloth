CodeSloth setup

CodeSloth groups a large pull request into ordered layers so you can review it bottom-up. It runs entirely in your browser and only reads from GitHub, using a fine-grained personal access token that you create and paste here. No app registration, no backend.

Current token

Your token is stored only on this device, in CodeSloth's extension storage. GitHub pages, other websites and other extensions can't read it. It's sent only to api.github.com, for read-only requests, and only when you open CodeSloth on a pull request. Remove it anytime with Clear token, or by removing the extension.

1 · Create a read-only token on GitHub

Who owns the repositories you review?

Repos under your own account (github.com/you/…).

Opens

  1. Token name: pre-filled as CodeSloth (read-only).
  2. Expiration: pre-filled to 90 days. Shorter is fine; avoid "No expiration".
  3. Resource owner: leave it as your own account.
  4. Repository access: Only select repositories and pick the repos you review (GitHub can't pre-fill this). All repositories also works but grants more than needed.
  5. Permissions → Repository permissions: Contents: Read-only and Pull requests: Read-only (pre-filled). Metadata: Read-only is added automatically. Add nothing else.
  6. Click Generate token and copy it (it starts with github_pat_).

Repos that belong to an organisation (github.com/your-org/…), e.g. Wayground. GitHub's pre-filled link doesn't work reliably here, so this opens the plain token page and you fill it in by hand.

Opens

  1. Token name: type CodeSloth (read-only).
  2. Expiration: pick 90 days or less. Your org may cap the maximum lifetime.
  3. Resource owner: choose the organisation, not your own account. If it isn't in the list:
    • the org must allow fine-grained personal access tokens (an org owner sets this under the org's Settings → Personal access tokens);
    • if the org uses SAML single sign-on, open the org on github.com and sign in through SSO first, then reload the token page.
    If the org asks for a justification, write something like "Read-only token for the CodeSloth extension to read pull requests."
  4. Repository access: Only select repositories and pick the repos you review. All repositories also works but grants more than needed.
  5. Permissions → Repository permissions: set Contents to Read-only and Pull requests to Read-only. Metadata: Read-only is added automatically. Leave everything else at No access: no "Read and write" and no organisation or account permissions.
  6. Click Generate token and copy it (it starts with github_pat_).
  7. Admin approval: many orgs require an org admin to approve new tokens. Until then GitHub lists the token as Pending, and it can only read public repos, so CodeSloth can't load private PRs. Ask an org admin to approve it. Org owners are approved automatically.
  8. Paste the token below.

"Repository not found" or 404?

GitHub answers 404 (not 403) when a token can't see a private repo. Check these:

  • Wrong resource owner. The token was created for your account but the repo belongs to an org (or the other way round). A token can only reach one owner, so create a new one with the right owner.
  • Repo not selected. With Only select repositories, the repo must be in the list. Edit the token on GitHub and add it.
  • Approval pending. The token shows Pending under your fine-grained tokens. It works only after an org admin approves it.
  • SSO. If the org uses SAML SSO, sign in to the org through SSO in this browser, then validate again.
  • Permissions. Contents and Pull requests must both be Read-only (not No access).

2 · Paste and validate

Your token is stored only on this device, in CodeSloth's extension storage. GitHub pages, other websites and other extensions can't read it. It's sent only to api.github.com, for read-only requests, and only when you open CodeSloth on a pull request. Remove it anytime with Clear token, or by removing the extension.

Why the checkbox? GitHub doesn't let an extension read a fine-grained token's permissions, so write access can't be detected automatically. Classic tokens are rejected outright. CodeSloth itself only ever sends GET requests.

Settings

Code font (file names, folders, SHAs and graph labels in the panel; OpenDyslexic is a dyslexia-friendly option)

The fonts ship inside the extension (SIL Open Font License); nothing is loaded from the web. Also available from Aa in the panel's tab row. Changes apply to open PR tabs right away.

Privacy

The token lives in CodeSloth's chrome.storage.local on this device. Access is restricted to the extension's own pages and background worker; github.com pages, the in-page panel and other extensions can't read it. It's sent only as the Authorization header of GET requests to api.github.com, when you open CodeSloth on a pull request. Like other browser data it isn't separately encrypted; it's protected by your OS user account and browser profile. PR code is processed locally and never sent anywhere else.
